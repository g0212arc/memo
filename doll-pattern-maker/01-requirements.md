# 01. 要件定義

## 1. 目的

- ドールのボディ採寸値から、**原寸の型紙**を作る
- 一度作った型紙を、**別のボディ（別メーカー・別スケール・別体型）に合わせて自動で作り直す**
- 人の入力作業を最小にする。利用ごとに課金が発生しない（サブスクの範囲内で運用できる）

### 想定する対象ボディ
特定のボディ専用にはしない。下のサンプル5体は**参考・テスト用**で、実際には手持ちのいろいろなボディを実測して使う。
サンプルは「このくらいの幅に対応できること」の目安とする。

| ボディ | 身長（頭なし） | 特徴 |
|---|---|---|
| 猎鹰体 | 48cm | 1/3 男性。胸囲とウエストの差が大きい |
| 大福体 1/4 | 38.5cm | 女性。胸パーツ4種 |
| 甘蔗三代 | 27cm | 1/6 前後。足パーツ2種 |
| 大福体 1/6 | 26.5cm | 大福体 1/4 と同じ体型でサイズ違い |
| 甜瓜体 | 18.7cm | 寸胴のデフォルメ体型（胸囲≒ウエスト） |

→ **スケールは約 18〜50cm、体型は大人〜デフォルメまで**を想定する。

---

## 2. 方式

### 2.1 作図は「採寸値をそのまま使う」
人間用原型（文化式など）の「胸囲÷n＋定数」のような比率式は使わない。
各点は、ボディの採寸値とゆとり量から直接計算する。

### 2.2 型紙は「寸法の式」で持つ（パラメトリック方式）
型紙の点を座標ではなく式で保存する。ボディを切り替えると式を再計算して型紙を引き直す。

```
例）前身頃・脇点 = (胸囲/4 + ゆとり(胸), 袖ぐり深さ)
    袖口幅      = max(上腕回り + ゆとり(袖), 手の通過周り + 通過余裕)
```

- **原型**（前後身頃・袖・パンツ）を式で定義する
- **デザイン**（丈、襟、フリル、切り替えなど）は「原型からの変更」として記録し、ボディを変えてもデザインが保たれるようにする

### 2.3 既存型紙の取り込み（方式B）は作らない
既存の型紙がまだないため、型紙はすべてこのツールで新しく引く。SVG/DXF の型紙を読み込んで伸縮する機能は範囲外とする。

## 3. 機能要件

### F1. ボディ管理
| ID | 要件 |
|---|---|
| F1-1 | ボディを複数保存できる。保存先はブラウザ内＋JSONファイルとして書き出し／読み込み |
| F1-2 | 採寸値は [共通採寸項目](02-measurement-schema.md) で持つ |
| F1-3 | 1つの項目に**バリエーション**を持てる（例: 胸パーツ4種、足パーツ2種、首2種）。型紙を作るときにどれを使うか選ぶ |
| F1-4 | 各値に**出どころ**を持つ: `maker`（メーカー公表値）／`measured`（自分で実測）／`estimated`（ツールの推定） |
| F1-5 | 画面上で推定値を色分けして表示し、クリックで実測値に上書きできる |

### F2. 採寸の取り込み（①方式）
| ID | 要件 |
|---|---|
| F2-1 | [定型プロンプト](03-body-import-prompt.md) を画面からワンクリックでコピーできる |
| F2-2 | Claude アプリの返答を**そのまま全文貼り付け**でよい（前後の説明文があっても JSON 部分を自動で取り出す） |
| F2-3 | 取り込み時にチェックし、問題を一覧表示する: 未知の項目、あり得ない値（例: ウエスト > 身長）、頭込み／頭なしの曖昧さなど |
| F2-4 | AI には**書き写しだけ**させ、推定はさせない。推定はツール側の決まった計算で行う（結果を再現できるようにするため） |
| F2-5 | 自分で実測した値も同じ流れで取り込める（手書きメモやスマホのメモのスクショを Claude アプリに貼る） |
| F2-6 | 取り込んだ後、**そのボディで作りたいアイテムに足りない項目だけ**を一覧にし、測り方の図を付けて表示する |

### F3. 不足項目の自動推定
| ID | 要件 |
|---|---|
| F3-1 | 型紙に必要なのにメーカーが載せていない項目（背丈、袖ぐり深さ、上腕回りなど）を、あるデータから推定する |
| F3-2 | 推定式は1か所にまとめ、根拠と一緒に記述する（後から調整できるように） |
| F3-3 | 推定値を使った型紙には「推定値を含む」と表示する |

> 例: どのメーカーも背丈を載せていない。「頭なし身長 − 外脚長」から胴の長さを出し、首の分を差し引く、などで推定する。
> 推定はあくまで仮の値。実測できるボディは実測値を入れる前提とし、推定式は実測値が集まったら見直す。

### F4. 型紙（原型とデザイン）
| ID | 要件 |
|---|---|
| F4-1 | 原型を式で定義する: 身頃・袖・パンツ・スカート（詳細は [04-items.md](04-items.md)） |
| F4-5 | 対象アイテムは **Tシャツ、ノースリーブタートルネック、ハーフパンツ、スカート** の4種。この順に作る |
| F4-2 | ゆとり量（胸・ウエスト・ヒップ・袖など）を調整できる。布の厚み別プリセット（薄手／普通／厚手）を持つ |
| F4-3 | 胸囲とウエストの差からダーツ量を自動で決める |
| F4-4 | デザインの変更（丈の増減、襟の形など）を原型からの変更として保存する |

### F5. 作り直し・比較
| ID | 要件 |
|---|---|
| F5-1 | ボディを切り替えると型紙を即座に再計算する |
| F5-2 | 2体の型紙を**重ねて表示**して比べられる（同じ縮尺で／同じ大きさにそろえて） |
| F5-3 | 1つの型紙を複数ボディ分まとめて書き出せる |

### F6. チェック
| ID | 要件 |
|---|---|
| F6-1 | 頭・手・足が開口部（襟ぐり＋開き、袖口、裾）を**通るか**を確認し、通らなければ警告する |
| F6-2 | 縫い合わせる線どうしの長さの差（袖山と袖ぐり、前後の脇線など）を表示する |

### F7. 出力
| ID | 要件 |
|---|---|
| F7-1 | **原寸PDF**。A4に分割し、貼り合わせ用の目印と、確認用の正方形（3cm角）を入れる |
| F7-2 | SVG 出力 |
| F7-3 | DXF 出力（うさくす等の CAD で続きを描けるように）。うさくすで読み込めるかは要検証 |
| F7-4 | 縫い代を付けて出力できる。初期値 5mm、変更可。できあがり線と裁ち切り線を両方描く |
| F7-5 | 型紙にボディ名・パーツ名・布目線・合印・日付を入れる |

## 4. 非機能要件

| 項目 | 要件 |
|---|---|
| 動作環境 | ブラウザだけで動く。**PC で編集、スマホは閲覧と PDF 保存だけ** |
| 通信・課金 | **型紙の計算に AI も外部通信も使わない**。利用ごとの課金はゼロ |
| データの保存 | ブラウザ内に保存＋JSONで書き出し。サーバーは持たない |
| 精度 | 内部計算は 0.1mm 単位。PDFは100%印刷で原寸になる |
| 拡張性 | 採寸項目・推定式・原型は後から追加しやすい構成にする |

## 6. やらないこと（今回の範囲外）

- ツール内から AI の API を呼ぶ（従量課金になるため）
- 自由に線を描く CAD 機能（うさくす等に任せ、DXFで受け渡す）
- アカウント、クラウド同期、共有機能
- 既存型紙の読み込み（方式B）

## 今後の相談メモ（Tシャツの試作が終わってから相談）

### 追加したいアイテム
- タートルネック、ラグランT、Yシャツ、長ズボン、短パン、円スカート（角度を自分で決められる）、ワンピース
- デザイン画の例: 襟つきジャケット（シングルカラー）、セーラー襟を改造したショートジャケット

### デザイン画から型紙を作る（案）
- 採寸画像と同じ流れ: デザイン画を Claude アプリで「デザイン仕様」（身頃の丈・襟の種類・袖・カフス・前開き・ポケットなどの組み合わせ）の JSON にし、ツールに貼り付ける
- ツールは部品（身頃・袖・襟・カフス・ポケットなど）を採寸値から計算して組み合わせる。ツール本体に AI は使わない方針のまま
- 絵だけで決まらない寸法（襟の幅、丈、ゆとり）は、確認して決める
- 部品にない特殊な形は作れない。よく使う部品から増やす

### サイトの運営（手書きメモより）
- サイトに広告を付けたい
- 管理者モードを付けたい
- ドールのボディデータは管理者だけが登録する
- ユーザーは手入力でサイズを変えられるが、保存はされない（JSON の書き出しは可）
- ユーザーの JSON 取り込みも可（保存はされない）
- ※ 管理者モードやボディデータの一元管理には、VPS 側のデータ保存とログインが必要（今の「ブラウザだけで完結」からの大きめの変更）
