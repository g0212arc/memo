# 05. 設計（フェーズ1）

フェーズ1の範囲: ボディ管理、JSON取り込み、不足項目の推定、身頃原型・袖原型、**Tシャツ**、原寸PDF・SVG、スマホでの閲覧。

## 1. 技術構成

| 項目 | 採用 | 理由 |
|---|---|---|
| 言語 | TypeScript | 型紙の計算は数値が多く、型があると間違いに気づきやすい |
| ビルド | Vite | 設定が少なく、静的ファイルとして書き出せる |
| 画面 | フレームワークなし（素の DOM 操作） | 画面が小さく、依存を増やさないため |
| PDF | jsPDF | 線をベクターで描け、mm 単位で原寸を指定できる |
| テスト | Vitest | 型紙の計算（推定・作図・縫い代）を自動で確認する |
| 公開 | 自分の VPS（docker compose + nginx:alpine） | 静的ファイルだけなので軽い。スマホから URL で開ける |

## 3. 「式で型紙を持つ」の実装方法

型紙は、**採寸値とパラメータを受け取って線を返す関数**として書く。

```ts
draftTshirt(body: 解決済み採寸値, params: Tシャツのパラメータ) → Piece[]
```

- ボディを切り替える → 同じ関数に別の採寸値を渡すだけで作り直せる
- デザインの変更（着丈、袖丈、開きなど）は `params` に入る。ボディを変えても `params` は保たれる

内部の単位は **cm**。出力（SVG/PDF）で mm に変換する。

## 4. 推定（estimate.ts）

画像にない項目は以下の順で埋める。すべて「推定値」として表示し、実測値を入れれば置き換わる。

| 項目 | 推定のしかた（仮） |
|---|---|
| 首回り | 胸囲 × 0.36（サンプル14体で 0.26〜0.52 倍、中央値約 0.36。差が大きいので推定したときは必ず実測をすすめる警告を出す） |
| 腕の長さ | 頭なし身長 × 0.33（サンプルで 0.31〜0.35 倍） |
| 肘が通る周り | 上腕回り × 1.15 ＋ 0.3cm（球体関節の出っ張りを見込む） |
| 肩幅 | 胸囲 × 0.53（サンプル12体で 0.38〜0.57 倍。推定したときは実測をすすめる警告を出す） |
| 首の長さ | 頭なし身長 × 0.055 |
| 股上 | 外脚長 − 股下。ただしヒップの 15% 未満なら不自然とみなし、ヒップ × 0.25 に切り替えて警告 |
| ウエストの高さ | へそ〜足裏があればそれ。なければ 股下 ＋ 股上 |
| 背丈 | 頭なし身長 − 首の長さ − ウエストの高さ。胸囲の 30〜75% を外れたら警告 |
| 前丈 | 背丈 ×1.02。胸囲とウエストの差が大きい（胸囲/ウエスト > 1.3）ときは差の 8% を足す |
| 上腕回り | 胸囲 × 0.32 |
| 腕の付け根回り | 上腕回り × 1.4（上腕回りもなければ胸囲 × 0.42） |
| 腰丈 | 背丈 × 0.45 |

※ 係数はサンプル5体で不自然にならないよう置いた仮の値。実測値が集まったら見直す。

## 5. Tシャツの作図

### 身頃（半身で作図）
1. 胸のできあがり寸法 G = 胸囲 ＋ ゆとり。ゆとりは「採寸値 × 割合 ＋ 固定分」（下の表）
2. 襟ぐりの幅（片側）= 首回り/6 ＋ 首回りの5%、後ろ襟ぐりの深さ = 幅/3、前襟ぐりの深さ = 幅 ×1.1 ＋ 調整
3. 肩先 = 肩幅/2（Tシャツは少し延ばす）。肩の傾きは 後ろ18°・前22°
4. 胸の線の高さ = 前後の袖ぐりの長さが「腕の付け根回り × (1 ＋ ゆとり)」になる深さを**二分法で求める**（ゆとり: 布帛 10%・ニット 3%。背丈の 8 割より深くはしない）
   - 当初は「腕の付け根回り/2」で決めていたが、肩幅が胸幅より広いボディ（猎鹰体）で袖ぐりが短くなりすぎたため変更
5. 袖ぐり = 肩先 → 背幅（前幅）の点 → 脇の点 をベジェ曲線でつなぐ。背幅・前幅は胸幅の 9 割程度までに抑え、袖ぐりの底を滑らかにする
6. 脇線は胸の点から裾までまっすぐ。裾がヒップより下なら、ヒップの寸法まで広げる
7. 背中開きありのとき: 後ろ中心に持ち出し（胸囲の5%、0.6〜1.5cm）を足し、後ろは「2枚（左右反転）」。なしのときは後ろも「わ」

### ゆとり（`app/src/pattern/ease.ts`）
ゆとり ＝ 採寸値 × 割合 ＋ 固定分（布の厚み・関節の出っ張りの分）。固定分はドールの大きさに関係なく同じなので、小さいドールほど割合が大きくなる。

| 部位 | ニット | 布帛 |
|---|---|---|
| 胸 | 胸囲 × 3% ＋ 0.2cm | 胸囲 × 10% ＋ 0.5cm |
| ヒップ | ヒップ × 2% ＋ 0.2cm | ヒップ × 8% ＋ 0.4cm |
| 袖幅（上腕回りに足す） | 上腕回り × 8% ＋ 0.3cm | 上腕回り × 20% ＋ 0.3cm |
| 袖ぐり（腕の付け根回りに足す） | × 6% ＋ 0.3cm | × 10% ＋ 0.4cm |
| 肘・手が通る余裕 | 0.1cm（伸びる分を見込む） | 0.3cm |

- 試作の感想（袖口が肘でつっかえる、袖幅・袖ぐりはもう少し大きくてよい）を受けて、2026-10-02 に袖ぐりと袖幅を広げた
- 画面の「袖幅を足す」「袖ぐりのゆとりを足す」で、人ごとの好みに合わせて調整できる

### 袖
1. 袖幅 = max(上腕回り ＋ ゆとり, 袖ぐりの長さ × 0.88（ニット）／0.75（布帛）, 肘が通る周り ＋ 余裕) ＋ 画面の「袖幅を足す」
   - 袖口も「肘が通る周り ＋ 余裕」より細くしない（着せるとき肘の関節が袖口を通るため。試作で肘がつっかえた指摘を受けて追加）
2. 袖山の高さを決め、袖山の曲線の長さが「前後の袖ぐりの長さ（＋いせ分）」に一致するよう、**数値計算で袖山の高さを自動調整**する
3. 袖丈 = 腕の長さ × 袖丈率（初期値 0.3 ＝ 半袖）

### 襟ぐりの始末
- 縁取り布（ニット: 襟ぐりの長さ × 0.85、布帛: バイアス布で × 0.95）を長方形のパーツとして出す

### 縫い代
- 辺ごとに種類を持つ: 縫い合わせ（初期値 5mm）、裾・袖口（初期値 8mm）、わ（0）、開き（初期値 8mm）
- 各辺を外側に平行移動し、角は隣の辺との交点でつなぐ（鋭すぎる角は切り落とす）
- ドールは襟ぐりなどのカーブの半径が縫い代より小さいことがあり、ずらした線が自分と交差して小さな輪ができる。交差を見つけて輪を取り除く

## 6. 出力

- **画面**: 1cm 方眼の上にパーツを並べて表示。推定値を使った項目と警告を一覧表示
- **SVG**: mm 単位（原寸）
- **PDF**: A4 縦、余白 10mm。パーツを並べた全体を A4 に分割し、各ページに「行-列」の番号と貼り合わせ用の目印を入れる。1ページ目に 3cm 角の確認用正方形
- 日本語や中国語の文字（ボディ名など）は、PDF にフォントを埋め込むと数MBになる。そのため、**文字だけ画像にして貼り、線はベクターのまま**にする

## 7. 公開

- 自分の VPS に docker compose で置く（nginx:alpine のコンテナ1つ、127.0.0.1:8200、メモリ上限 64MB）。ホストの nginx が https://tcpattern.duckdns.org で受けて転送する
- 手順は [deploy/README.md](deploy/README.md)。更新は VPS で `deploy.sh` を実行
- `.github/workflows/doll-pattern-maker.yml` は、`doll-pattern-maker/` を変更して push するとテストとビルドを実行する（公開はしない）
- 当初は GitHub Pages を予定していたが、VPS があるため変更（デフォルトブランチや非公開リポジトリの制約を避けられる）
