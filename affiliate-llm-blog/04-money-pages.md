# 04. 収益ページ設計 — 月3〜5万の中核

## なぜ5本必要なのか

検証記事と収益ページは**読者の状態が違う**。

- 検証記事の読者 = 「調べている」 → リンクを踏むが買わない
- 収益ページの読者 = **「買うかどうか決める直前」** → 踏んだら買う

いま持っている記事はほぼ全部が前者。だから、いくらリンクを足しても
成約はパーツのついで買いに留まる。**「決める直前の読者」が着地する場所を作る**のが、
単価400円のブログを単価3,000円のブログに変える唯一の方法。

## 5本の共通ルール

- **新しい検証をしない。** 5本とも、すでに持っている実測データと自分の体験だけで書ける
- **1本 90〜120分。月1本ペースで5ヶ月。**それ以上速く書かない（→ [07](07-operations.md) のロードマップ）
- 構造は共通: ①結論の表 → ②測定環境 → ③選択肢ごとの実費と実測 → ④損益分岐 → ⑤型1ブロック → ⑥高単価枠1つ
- **冒頭に結論の表を置く。**「調べに来た人」を待たせない。読み進めた人だけが下のリンクに届く
- 既存の検証記事から、この5本へ内部リンクを張る（各記事の型1ブロックの下に1行）

## M1 —「ローカルLLM用PCの選び方：GPU単体で組む / 中古ゲーミングPC / 新品BTO」

| | |
|---|---|
| **読者の状態** | 予算を決めて、どれを買うか比較している |
| **着地エンジン** | **① PC本体（Amazon・上限なし）** ＋ ③パーツ |
| **想定単価** | 2,000〜5,000円 |
| **書ける根拠** | 自分で組んだ実費と、その後の実測がある |

### 中身

3つの選択肢を、**同じ表で並べる**。

| | GPU単体で組む | 中古ゲーミングPC | 新品BTO |
|---|---|---|---|
| 初期費用 | 実費を書く | 実費を書く | 実費を書く |
| 手間 | 組み立て・相性 | 届いてすぐ | 届いてすぐ |
| 失敗リスク | 電源容量、ケース幅 | 電源が弱いことが多い | ほぼない |
| 向いている人 | | | |

**この記事の要点は「中古ゲーミングPCという選択肢を正面から扱うこと」。**
3060搭載の中古ゲーミングPCは、GPU単体で買ってケース・電源・CPUを揃えるより
トータルで安く済むことがある。読者の多くはそれを知らない。
そして**PC本体1台の成果はパーツ10個分**にあたる。

正直に書くべきこと（これがあるから読まれる）:
- 中古ゲーミングPCは**電源が弱い個体が多い**。3060を積んでいても500W以下だと2枚目は無理
- ケース内のエアフローが悪くサーマルスロットリングする個体がある
- 「自分は結局こうした」という結論を最後に1行

## M2 —「RTX 3060 12GBで動くモデル一覧（実測 tok/s・VRAM使用量）」

| | |
|---|---|
| **読者の状態** | 3060を買うか判断中／すでに持っていて何が動くか調べている |
| **着地エンジン** | ①PC本体、③3060本体・SSD・メモリ |
| **想定単価** | 600〜3,000円 |
| **書ける根拠** | **既存記事の数字を1枚に集約するだけ** |

### 中身

既存の検証記事に散らばっている数字を、1つの表に集める。

| モデル | 量子化 | VRAM使用量 | tok/s | コンテキスト上限 | 日本語の印象 |
|---|---|---:|---:|---:|---|

- これが**Xの固定ポストとプロフィールの飛び先**になる（→ [06](06-x-profile.md)）
- 全検証記事からの内部リンク先にもなる
- **更新が最も軽い。** 新しいモデルを試すたびに行を1つ足すだけ。それ自体が趣味の延長

> 前の版で「機材まとめハブ記事」と呼んでいたものは、このM2に統合する。

## M3 —「VRAMが足りない時の4つの選択肢：2枚差し / 上位GPU / クラウドGPU / API課金」

| | |
|---|---|
| **読者の状態** | **12GBの限界にぶつかった直後**。一番お金を使う状態 |
| **着地エンジン** | **② VPS・GPUクラウド（最重要）** ＋ ①PC本体 |
| **想定単価** | **3,000〜10,000円** |
| **書ける根拠** | 12GBの限界を実測で知っている。有料AIも複数使っている |

### 中身 — **5本のうち、これが一番効く**

4択を同じ土俵で比較する。

| | 3060 2枚差し | 上位GPU 1枚 | クラウドGPU | API課金 |
|---|---|---|---|---|
| 初期費用 | | | 0円 | 0円 |
| 月額 | 電気代 | 電気代 | 時間課金 | 従量 |
| 実測速度 | | | | |
| 使える最大モデル | | | | |
| 向いている使い方 | | | | |

**損益分岐を必ず出す。**「月◯時間を超えたら手元GPUのほうが安い」という1行が、
この記事の価値のほぼ全部で、そこにクラウドGPUのリンクが自然に置ける。

正直に書くべきこと:
- **「月に数時間しか使わないならクラウドのほうが確実に安い」** と書く。
  手元GPUを勧めないほうが、結果的にどちらのリンクも踏まれる
- 2枚差しはライザー・電源・ケースの問題があり、誰にでも勧められる構成ではない

## M4 —「ローカルLLMの電気代を実測した：月いくらかかるのか」

| | |
|---|---|
| **読者の状態** | 常時稼働を検討中／ランニングコストが不安 |
| **着地エンジン** | ②VPS（比較として）、③ワットチェッカー・電源 |
| **想定単価** | 100〜5,000円 |
| **書ける根拠** | ワットチェッカーで実測している |

### 中身

- アイドル時／推論時／学習時の実測W
- 1日1時間・3時間・24時間での月額換算（単価31円/kWh などの前提を明記）
- **クラウドとの損益分岐**（M3へ内部リンク）
- 電源効率（80PLUS等級）で実際どれくらい変わったか

ワットチェッカー自体の成果は数十円だが、**踏みやすい安価品リンク**として機能する。
Amazonのクッキーは24時間有効なので、ここを踏んだ読者がその後に買う高額品も成果になる。

電力プラン切替のASP案件（1件3,000〜8,000円）を置くかは任意。
**自分が実際に切り替えたときだけ**書く。やっていないなら置かない。

## M5 —「ローカルLLM vs Claude / GPT 課金：1年使った実費の比較」

| | |
|---|---|
| **読者の状態** | どちらに課金するか迷っている |
| **着地エンジン** | ①PC本体、②クラウド |
| **想定単価** | 2,000〜5,000円 |
| **書ける根拠** | **自分がまさに両方の当事者** |

### 中身 — **他の誰にも書けない記事**

有料AIを複数契約しつつ、3060でローカルも回している人はほとんどいない。
そこで得た「実際どっちをどう使い分けているか」は、検索需要が大きいのに書ける人が少ない。

- 初期投資（PC/GPU）を12ヶ月で割った月額 ＋ 電気代 = ローカルの実費
- 有料AIの月額実費（何を何本使っているか）
- **用途ごとの使い分け**（ここが本題）: 速度、品質、プライバシー、止まらないこと
- 「結局こうしている」という結論

この記事は**売り込みが一切要らない**。実費を並べるだけで、読者が勝手に自分の状況で判断する。
[05-writing-rules.md](05-writing-rules.md) の「記録する」がそのまま形になった記事になる。

## 書く順番

| # | 記事 | 理由 |
|---|---|---|
| 1 | **M2**（動くモデル一覧） | 既存の数字を集めるだけで一番軽い。Xの飛び先が先に要る |
| 2 | **M3**（VRAM不足の4択） | **単価が最も高い。**早く出して検索順位を育てる |
| 3 | **M1**（PCの選び方） | 単価2位。M3から内部リンクが張れる |
| 4 | **M5**（ローカル vs 課金） | 書きやすく、拡散しやすい |
| 5 | **M4**（電気代） | 土台。M3・M5から流入する |

M2 → M3 の順にするのは、**M3が育つのに一番時間がかかるから**。
早く公開して、順位が上がるのを待つ時間を長く取る。
